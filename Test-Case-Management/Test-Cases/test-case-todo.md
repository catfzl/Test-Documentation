Showcases various test cases across different testing types, including functional, non-functional, and automated tests.

# Functional Tests:
* Integration Tests: Test cases that verify the integration between different modules or components of the system.
* Smoke Tests: A subset of test cases that quickly verify the core functionality of the system.
* Regression Tests: Test cases that ensure existing functionality is not affected by new changes.
* E2E Tests: Test cases that cover end-to-end user scenarios, simulating real-world user interactions.

# Non-Functional Tests:
* Performance Tests: Test cases that evaluate the system's performance under different conditions (e.g., load testing, stress testing).
* Security Tests: Test cases that assess the system's security vulnerabilities and defenses.
* Usability Tests:
    * UI Tests: Test cases that focus on the user interface and its effectiveness.
    * Accessibility Tests: Test cases that ensure the system is accessible to users with disabilities.
    * UX Tests: Test cases that evaluate the overall user experience.
* Compatibility Tests:
    * Browser Compatibility Tests: Test cases that verify the system works correctly across different web browsers.
    * Device Compatibility Tests: Test cases that ensure the system functions properly on various devices (e.g., desktops, laptops, tablets, smartphones).
* Automated Tests:
    * Includes a selection of automated test scripts (e.g., using Selenium, Playwright, API testing frameworks) to demonstrate your automation skills.

# Test Case Format:
Each test case will be documented in a separate Markdown file or within a single file organized by sections. The following information for each test case will be included:

* ID: A unique identifier for the test case.
* Title: A descriptive title.
* Description: A detailed description of the test case.
* Preconditions: Any conditions that must be met before executing the test case.
* Steps: A numbered list of steps to execute the test case.
* Expected Results: The expected outcome of the test case.
* Actual Results: The actual outcome of the test case1 (to be filled during execution).
